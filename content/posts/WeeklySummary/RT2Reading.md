我们来读一篇具身智能（Embodied AI）和机器人学习领域非常里程碑式的一篇论文（由 Google DeepMind 于 2023 年发表）。

它的核心标题非常直白地总结了整篇论文在做的事：

> **RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control**  
> （RT-2：视觉-语言-动作模型将互联网知识迁移到机器人控制中）

## 解决了什么痛点

以往的机器人学习模型（比如 RT-1）有一个致命弱点：**泛化能力弱，缺乏常识**。

- 如果你只教过机器人拿“红色的苹果”，它可能看到“青苹果”就不认识了；
- 如果你对机器人说“把快过期的水果扔进垃圾桶”，传统的机器人直接懵掉——因为它既不知道什么叫“过期”，也不知道香蕉变棕变黑代表“快过期”。

而大语言模型 / 多模态模型（VLM，比如 GPT-4V、PaLI-X、PaLM-E）在互联网的海量图文上训练过，它们懂常识、懂推理、认识万物，但它们“没有手脚”，不会输出机器人的电机控制指令。

RT-2 的核心贡献就是：

> **把机器人控制动作（Action）直接当成“自然语言词表”的一部分！**  
> 这样就能直接用预训练好的互联网级大模型（Vision-Language Model），一边保留互联网上的丰富常识与语义推理能力，一边直接输出机器人的机械臂末端位姿控制指令。这种模型架构被他们正式命名为 **VLA（Vision-Language-Action，视觉-语言-动作）模型**。

## 前人的研究

在论文发表之前，前人做了哪些工作呢？

论文里引用了大量前人研究（比如 RT-1、PaLM-E、SayCan、BC-Z 等），初读很容易被这些名词绕晕。其实整个脉络可以用“机器人学习进化的三部曲”来理解：

### 第 1 代：传统机器人学习（纯模仿学习 / 强化学习）

- **做法**：教机器人一个任务（比如拧瓶盖），机器人看摄像头，直接预测电机转多少度。
- **致命缺点**：极度“死脑筋”。桌子换个颜色、光线变一下、或者换了个没见过的杯子，机器人直接瘫痪。它完全没有“常识”。

### 第 2 代：尝试结合大模型（前作 SayCan 和 PaLM-E，RT-2 的直接前身）

大家发现：大语言模型（LLM/VLM）在互联网上读了万卷书，懂各种常识！于是科学家开始尝试把大模型搬到机器人上：

- **前作 SayCan（大脑与小脑分离）**：
  - **大脑**：大模型（比如 GPT-3）负责“出谋划策”，生成高层规划：“1. 走到桌前；2. 抓起可乐；3. 递给人”。
  - **小脑**：底层依然是传统机器人策略（预先训练好一个个固定动作库，比如专门抓取的策略）。
  - **缺点**：大脑不懂底层的物理细节，小脑又太笨，两边经常配合不好，而且底层的控制能力依然没有常识。
- **前作 RT-1（Robotics Transformer 1）**：
  - Google 做了一个专门针对机器人动作的 Transformer 模型，收集了十几万条真实的机器人操作轨迹。
  - **缺点**：虽然动作学得不错，但它是一个从零开始训练（from scratch）的模型，没有互联网上千亿级图文知识的滋养，遇到没见过的物体、或者需要复杂常识推理的指令（比如“把濒临灭绝的动物玩偶拿给我”），它根本不知道哪个动物濒临灭绝。

### 第 3 代：RT-2（本文阐述的核心创新）

作者提出了一个非常大胆、但极其优雅的想法：

> 为什么非要区分“大脑”和“小脑”？  
> 能不能直接把一个在互联网上海量图文上训练好的成熟大模型（VLM），直接改造成控制机械臂的模型？

它要阐述的事情只有一句话：

> **只要把机器人的物理动作表示成大模型能懂的“文本词元（Token）”，大模型原有的海量常识、语义推理、识别万物的能力，就能瞬间无缝迁移给机器人的手臂！**

## 动作怎么变成词元

这是 RT-2 最精妙的地方。大语言模型本质上是一个“文字接龙游戏”——输入一段话/一张图，它预测下一个出现的 Token（词元）。

机械臂的动作明明是一堆连续的物理浮点数（比如 X 轴移动 0.12 米，夹爪开合度 0.85），怎么变成“词”呢？

![机器人动作的“词元化”三步流水线](/images/rt2/action_tokenization_pipeline.png)

### 1. 机械臂动作包含什么？

RT-2 控制的机械臂在每个时间步需要输出 8 个维度的数值：

| 维度 | 含义 |
| :--- | :--- |
| `x` | 前后平移变化量 |
| `y` | 左右平移变化量 |
| `z` | 上下平移变化量 |
| `roll` | 横滚角旋转 |
| `pitch` | 俯仰角旋转 |
| `yaw` | 偏航角旋转 |
| `gripper` | 夹爪开合状态（`0` 表示开，`1` 表示闭） |
| `terminate` | 任务是否结束的标志（`0` 或 `1`） |

### 2. 离散化装箱（Quantization / Binning）

大模型不能直接输出无穷精度的连续实数（比如 0.123456...），但可以输出离散的整数等级。作者把每一个维度的可能取值范围（比如 `[-1, 1]` 米），平均切成 256 个小格子（bins）：

- **最小的极限值**对应数字：`0`
- **中间值**对应数字：`128`
- **最大的极限值**对应数字：`255`

这样一来，连续的一串浮点数动作，就被转成了 8 个在 0 到 255 之间的整数。

| 步骤 | 示例 |
| :--- | :--- |
| 真实的物理动作 | `[+0.05, -0.02, +0.10, 0°, +5°, 0°, 闭合, 未结束]` |
| 离散化后的整数 | `[132, 120, 145, 128, 135, 128, 255, 0]` |

### 3. 把整数直接借用为模型词表里的 Token！

这是最绝的一步！大模型的词表通常很大（比如有 32,000 个词或更多）。

作者直接说：不用加特殊的动作硬件接口，直接借用词表里的前 256 个文本 Token，或者直接把它们当成文本字符串！

在模型眼里，输入和输出变成了完全标准的文本生成格式：

- **输入（Prompt）**：
  - 一张摄像头当前拍到的照片
  - 一句人类指令：“把草莓放进碗里”
- **模型的输出（Output）**：
  - 直接生成一串文本，例如：`"132 120 145 128 135 128 255 0"`

机器人底层的驱动程序拿到这串由大模型生成的文本数字后，做个简单的反向查表（De-quantization），把 `132` 还原回电机应该移动的毫米数，机械臂就动起来了！

## 这样设计带来了什么变化

如果你问传统机器人：“请把灭绝的动物拿起来”，桌上放着恐龙玩具和狮子玩具：

- **传统机器人**：完全不知道“灭绝”是什么，因为它的训练集里只有“拿狮子”、“拿恐龙”。
- **RT-2**：
  1. 它在预训练阶段（看遍维基百科和全网图文）就知道：“恐龙是灭绝的动物”；
  2. 它在视觉编码器里看到桌上有个恐龙玩具；
  3. 于是，它成功将语义指令连接到了恐龙的位置；
  4. 随后，它把这个目标位置顺理成章地预测成对应的动作数字 Token：`"128 140 85 ..."`。

> **常识推理 + 动作生成，在同一个神经网络里一气呵成！**
